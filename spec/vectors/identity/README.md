# Identity vectors

Each file pins a part of [identity.md](../../identity.md). `tools/digest.py --check-examples` checks all four.

- **`examples.json`** (`"kind": "fx-identity-examples-v1"`): the worked examples of identity.md §14.
  - An example with `object` (or `object_source`, a JSON text) must canonicalize to `canonical` and hash to `digest`. A hashed object names its formula in `kind`, and rebuilding it through that formula must give the same digest.
  - An example with `file_utf8` is a file of those UTF-8 bytes; `digest` is its file digest, and `text`, when present, is its content read as text (§5).
  - An example with `instance_id` is a name, not a digest (§11): `path` lists each level as `{"step"}`, with `"key"` on a repeated step, and `take` is the instance's take.
- **`markers.json`** (`"kind": "fx-marker-vectors-v1"`): reserved plain markers (§3). Each case's `json` is a JSON text. Read as an authored value (an inputs file, a workflow, a table, a JSON file), it must be refused when `refuse` is true and read as ordinary data when it is false. Every case is a valid I-JSON value, so a reader of runtime values (a graph, a record) reads all of them.
- **`json_output.json`** (`"kind": "fx-json-output-vectors-v1"`): the bytes a JSON output is written as (§5, "Writing JSON"). Writing the value of `value_json` must give exactly the UTF-8 bytes of `bytes_utf8`.
- **`routes.json`** (`"kind": "fx-route-vectors-v1"`): route tables read into a catalog, each contract completed (§7). A case's `builtin` stands in for the built-in default table, and its `tables` (each a table's `routes`) are read after it, in order; `routes_given` leaves the built-in table out of the catalog, as a `--routes` file does, though it still serves as a base for `extends`. Each item of `expect` is a route the catalog must hold, with its completed `contract` and its fingerprint, `digest`; each item of `absent` one it must not hold. A case with `refuse` must be refused while its tables are read, at that table's entry, for that reason: `no_base` (`extends` names a route no table read so far holds for the entry's capability) or `other_provider`. A case's `providers`, when given, is the planning project's declarations as `fx.yaml`'s `providers:` gives them; only a declaration's `family` completes a contract (§7 step 2). The models are made up; the providers are FX's own where a case needs an adapter of FX's, a declared `acme` where it needs a family's, and `acme` or `other` otherwise (`other` is never declared).
